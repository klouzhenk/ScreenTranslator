# Обфускація — захист скомпільованого коду

## Що це
Так, фактично **маскування**. Намірене ускладнення читання скомпільованого коду для людини (чи для decompiler'а), без зміни його поведінки в рантаймі. Той самий `UserService.Login(user, password)` після обфускації стає `a.b(c, d)`, зі скрізь порозкиданими «сміттєвими» інструкціями, зашифрованими рядками й розплющеним control flow.

Програма працює так само — просто **скомпільований вигляд** стає малоінформативним для того, хто спробує reverse-engineer.

## Чому це питання взагалі виникає в .NET
IL (intermediate language), у який компілюється C#, **дуже близький до вихідного коду**. Decompiler'и (ILSpy, dnSpy, dotPeek, decompile у JetBrains Rider) видають майже оригінальний C#:
- імена методів, класів, параметрів — збережені,
- структура коду зчитується,
- навіть XML-docs іноді залишаються в метаданих.

Це наслідок філософії .NET: метадані багаті, бо потрібні для reflection, interop, serialization. Платимо за це легкістю reverse engineering.

Порівняй з C/C++ — там exe це нативні машинні інструкції, імена здебільшого зникли ще на етапі компіляції. Decompile можливий, але вихід — малочитабельний.

## Що обфускатор типово робить
| Прийом | Приклад до → після |
|---|---|
| **Renaming** | `UserService.Login(username, password)` → `a.b(c, d)` або невидимі Unicode-символи типу `І`, `І`, `І` (різні, виглядають однаково) |
| **String encryption** | `"api.example.com"` → `Decode("eW14cXp2YQ==")` з розшифровкою в рантаймі |
| **Control flow flattening** | лінійний метод → `switch` з стрибками-goto, важко слідкувати |
| **Dead code injection** | додаються неробочі гілки, щоб заплутати аналіз |
| **Anti-debug** | код виявляє attached debugger і завершується / працює інакше |
| **Anti-tamper** | checksum самого exe, інтегрується з обфускатором |

## Інструменти для .NET
| Інструмент | Ціна | Коментар |
|---|---|---|
| **Obfuscar** | Free, open-source | Базовий renaming. Простий, достатньо для MVP-захисту |
| **Dotfuscator Community** | Free (у Visual Studio) | Mild renaming. Є платна Pro-версія для серйозного |
| **ConfuserEx** | Free, open-source | Потужний, але не оновлюється з ~2019, інколи ламає сучасний .NET |
| **Eazfuscator.NET** | Commercial (~$800/рік) | Один з найсерйозніших для реального продукту |
| **.NET Reactor, ArmDot** | Commercial | У тій самій лізі |

## Ціна обфускації (трейд-офи)
**Стек-трейси стають нечитабельними.** `at a.b()` замість нормальних імен → діагностика крашів складніша. Платні обфускатори дають **symbol map** — файл-перевідповідність, через який можна відновити оригінальні імена з обфускованого stack trace. Але map треба зберігати окремо і не загубити.

**Reflection і DI ламаються.** DI-контейнер шукає конструктори за типами, serializer — властивості за іменами, WPF binding — властивості за рядковими іменами. Якщо обфускатор перейменував `UserName` на `a7`, WPF шукає `UserName` і не знаходить. Виправлення: виключити з обфускації типи/властивості, помічені атрибутами, або явно виписати exclusion-правила у конфізі обфускатора.

**Не silver bullet.** Досвідчений реверсер і обфускований код прочитає — просто повільніше. Обфускація підвищує поріг входу, не робить код недоступним. Проти цільової атаки — потрібні серверні перевірки, не клієнтська обфускація.

**Білд-пайплайн ускладнюється.** Додатковий крок після `dotnet publish`, окремий конфіг, його треба підтримувати, тестувати що релізний білд не впав через обфускацію.

## Коли варто
- **Комерційний продукт** з ліцензійним кодом, перевірками серійника, захистом від piracy.
- **Enterprise-застосунок** з бізнес-логікою, яку компанія не хоче, щоб конкуренти легко прочитали.
- **Код з API-ключами всередині** (хоча це само по собі bad practice — ключі мають бути на сервері чи в змінних середовища, як у нас).

## Коли не варто
- **Open-source проєкти** — безглуздо, код у репозиторії.
- **Hobby / pet / MVP** — ціна в підтримці і діагностиці перевищує вигоду.
- **Self-contained + trimmed публікації** — trimmer і так обрізає багато метаданих, реверсити трохи складніше з коробки.

**Для ScreenTranslator — не варто.** Немає секретних алгоритмів, DeepL API-ключ береться зі змінної середовища (не в коді), застосунок роздаєш друзям. Якби з цього робили комерційний продукт з ліцензіями — тоді так, Obfuscar би був першим кроком.

## Альтернатива — Native AOT
`<PublishAot>true</PublishAot>` компілює IL у нативний код, метадані здебільшого відкидає. Decompile такого стає значно важчим — результат порівнянний з C++ exe. Побічний бонус поряд із швидким startup.

Але **для WPF Native AOT не підтримується** навіть у .NET 10 — див. [release-publishing.md](release-publishing.md). Для нашого проєкту цей варіант закритий.
