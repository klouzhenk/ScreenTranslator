# Журнал рішень — ScreenTranslator

Рішення, ухвалені під час обговорення ТЗ (жовтень 2026). Повне ТЗ — у `CLAUDE.md`.

## .NET 10 замість .NET 8
- .NET 8 і .NET 9 втрачають підтримку 10.11.2026; .NET 10 — LTS до листопада 2028.
- TargetFramework: `net10.0-windows10.0.19041.0` (суфікс відкриває WinRT API для `Windows.Media.Ocr`).

## UI: WPF
- Розглядали: WinForms, WPF, Avalonia, WinUI 3, Blazor Hybrid, MAUI, Tauri, Electron, Python, AutoHotkey.
- Blazor Hybrid / Electron відкинуто: WebView забирає фокус, прозорість складна, повільніший старт, а все складне в проєкті — Win32, не UI.
- MAUI відкинуто: на Windows це обгортка над WinUI, трей і оверлей незручні.
- Обрано WPF. Що з цього випливає:
  - **Трей** не вбудований: `H.NotifyIcon.Wpf` або WinForms `NotifyIcon` (`<UseWindowsForms>true</UseWindowsForms>`) — вирішити на етапі 1.
  - **Глобальний хоткей:** `RegisterHotKey` + `HwndSource.AddHook` для `WM_HOTKEY`.
  - **Вікно без фокусу:** `ShowActivated="False"` + `WS_EX_NOACTIVATE` через `SetWindowLongPtr` у `SourceInitialized`.
  - **DPI:** WPF працює в DIP (1/96 дюйма), знімок — у фізичних пікселях. Перерахунок в одному місці: виділення (DIP) × коефіцієнт DPI монітора (`VisualTreeHelper.GetDpi`) → координати для вирізання зі знімка. PerMonitorV2 — через маніфест.

## Архітектура: Generic Host
- `Microsoft.Extensions.Hosting` у WPF: прибрати `StartupUri` з `App.xaml`, будувати хост в `OnStartup` (аналог `Program.cs` в ASP.NET).
- DI для `IScreenCapture`, `IOcrService`, `ITranslationService`; `IOptions<T>` для конфігу; `IHttpClientFactory` для DeepL; `ILogger`.
- Причина: два роки досвіду з ASP.NET/Blazor — знайомі патерни, легко замінювати провайдерів.

## OCR: Windows.Media.Ocr
- Офлайн, безкоштовно, без залежностей. Порівнювали з Tesseract (гірше на скриншотах, треба tessdata) і хмарним OCR (мережа, ключ, затримка).
- За інтерфейсом `IOcrService`, щоб замінити за потреби.
- Порада: перед розпізнаванням збільшити зображення ×2 — підвищує точність.
- Потрібен встановлений пакет `Language.OCR~~~en-US` (особливо якщо Windows не англійська).

## Виділення: заморожений кадр замість прозорого оверлея
- Хоткей → знімок монітора під курсором → показ у непрозорому вікні на весь монітор (затемнено) → виділення мишкою → вирізання з готового знімка.
- Чому: не потрібна прозорість; текст не змінюється під час виділення (репліки «друкуються» по літері); кліки не потрапляють у гру; оверлей не потрапляє в знімок; простіше з DPI.
- Вікно виділення забирає фокус; перед показом — `GetForegroundWindow`, після — `SetForegroundWindow` (повернути фокус грі).
- «Повтор останньої області» робить **свіжий** знімок тієї ж області, без вікна виділення.

## Один монітор у MVP
- Монітор під курсором. Кілька моніторів із різним масштабуванням — найскладніший випадок для DPI, винесено «на потім».

## Ключ DeepL — у змінній середовища
- Не в репозиторії, не в `appsettings.json`. Назву змінної зафіксувати на етапі 4.
